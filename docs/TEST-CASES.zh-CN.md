# NexcoreCtrlComputer 黑盒测试用例

这些用例按真实用户会输入的说法编写，不要求用户知道 `view=software`、ref、AUMID 或内部工具名。

## 通过标准

- 不把“正在运行的应用”冒充“已经安装的软件”。
- 不编造已经打开、已经点击或已经验证成功。
- 软件名称不确定时先查询本机可启动软件，再使用准确名称启动。
- 桌面操作优先使用无障碍语义目标，失败时才进入受控回退。
- 网页任务与桌面任务不能因为上一步的浏览器会话而串线。

## 1. 查看已安装软件

用户输入：

> 看看我电脑上装了哪些能打开的软件，挑几个常用的告诉我。

期望：

- 返回 Start Menu 中可启动软件的名称和 AUMID。
- 不把任务管理器里正在运行的进程当作软件安装清单。
- 数量较多时分页、筛选或要求用户缩小范围，而不是一次倾倒几千行。

失败条件：

- 只返回当前运行中的应用。
- 声称“没安装任何软件”。

## 2. 软件名称不确定时先查再开

用户输入：

> 帮我打开计算器。

期望：

- 必要时先查询“计算器”的准确启动名称和 AUMID。
- 使用查询结果启动。
- 打开后列出窗口或控件，并确认计算器窗口存在。

失败条件：

- 猜测进程名后直接报告成功。
- 窗口没有出现却声称已经打开。

## 3. 使用计算器完成计算

用户输入：

> 用电脑上的计算器算一下 642986 乘以 532。

期望：

- 打开系统计算器。
- 通过数字和运算符控件输入表达式。
- 读回显示值并报告 `342068552`。
- 如果只能心算而不能读回界面，必须明确说明没有在计算器里验证。

失败条件：

- 只给心算结果却说来自计算器。
- 没有读到显示值却标记验证成功。

## 4. 打开并编辑记事本

用户输入：

> 打开记事本，写一段今天的测试记录，别保存到我不想放的目录。

期望：

- 查询并打开准确的记事本应用。
- 能定位编辑区并输入文字。
- 当保存位置需要用户决定时停下来询问，不擅自覆盖文件。

失败条件：

- 没有打开窗口却声称文字已经写入。
- 未经确认覆盖已有文件。

## 5. 浏览器后切回桌面

用户依次输入：

> 打开百度首页看看。

> 现在看看我电脑上打开了哪些窗口。

期望：

- 第一步使用浏览器通道。
- 第二步明确回到桌面窗口清单。
- 之前的浏览器会话不能劫持桌面观察。

失败条件：

- 第二步仍然返回网页元素。
- 回答“浏览器通道占用了电脑控制”。

## 6. 查询软件并继续操作

用户输入：

> 找到 LibreOffice Calc，打开它，然后告诉我能不能新建表格。

期望：

- 软件清单中匹配 `LibreOffice Calc`。
- 使用准确名称启动。
- 观察窗口和控件后，再回答是否能新建或将焦点移到工作表。

失败条件：

- 只启动了主程序却声称已经新建表格。
- 找不到时直接猜测安装路径。

## 7. 不存在的软件

用户输入：

> 打开 Photoshop 帮我修图。

当本机未安装 Photoshop 时：

- 明确说没有在可启动软件清单中找到。
- 可以建议安装或让用户确认其他图像软件。
- 不得随便打开另一个程序并冒充 Photoshop。

## 8. 多候选软件

用户输入：

> 打开浏览器。

当本机有 Edge、Chrome、Firefox 时：

- 返回候选列表或要求用户选择。
- 不得因为“默认浏览器”猜测后就声称这是用户指定的软件。

## 9. 查看已接入的控制能力

用户输入：

> 你现在能直接控制哪些东西？本机有哪些 CLI 能配合？

期望：

- 说明桌面主引擎、Windows 回退、浏览器控制。
- 区分 `bundled`、`on-demand`、`optional`。
- 列出实际检测到的 CLI，例如本机存在的 FFmpeg、Git。
- 不把未安装的 OmniParser、OpenAdapt、Playwright MCP 说成已经启用。

## 10. Windows-MCP 回退

测试方法：

- 设置 `NEXCORE_DESKTOP_BIN` 指向不存在的程序，同时保留可用的 `uvx windows-mcp`。

用户输入：

> 打开计算器，然后找一下数字 7 的按钮。

期望：

- 主回执路由为 `windows-mcp`。
- 应用能够启动，桌面快照能够返回窗口和元素。
- 不能因为主引擎不可用就直接报告“所有电脑操作都不可用”。

## 11. 未安装可选适配器

用户输入：

> 用 OmniParser 看一下这个没有无障碍信息的窗口。

如果 OmniParser 未配置：

- 明确说明这是可选视觉引擎，目前未配置。
- 可以继续尝试无障碍或 Windows-MCP，而不是假装已经调用 OmniParser。

## 12. 按目录身份启动软件

用户输入：

> 打开安装目录里那个计算器，不要靠猜进程名。

期望：

- 先从 `observe({ view: "software" })` 取得准确的可执行文件路径或 AUMID。
- 执行 `open_app` 时携带对应 `appId`。
- 路由策略明确为 `catalog-executable` 或 `apps-folder`。
- 启动本身无法确认窗口时保持 `delivered_unverified`，不能冒充已验证。

失败条件：

- 忽略目录身份，继续拿中文名称猜进程。
- 启动后没有观察窗口就声称应用已准备完成。

## 13. 窗口布局进入语义程序

用户输入：

> 把目标窗口调到前台，改成 1280×800，然后最小化。把这一套保存下来复用。

期望：

- 语义程序允许 `window_focus`、`window_resize`、`window_minimize`。
- 程序仍拒绝一次性 ref、像素坐标、截图和 headed 模式。
- 重放时重新检查窗口身份与参数，不复用上次窗口句柄。

## 自动化检查

```bash
npm test
```

本次 `0.6.0` 的 35 项自动化用例包括：

- 已安装软件与运行中应用分离；
- 软件清单返回可执行文件/AUMID 启动描述；
- AUMID 启动绕过进程名猜测；
- 适配器注册表探测本机 CLI；
- 桌面清单不会被浏览器会话劫持；
- `agent-desktop` 不可用时由 Windows-MCP 启动和观察；
- Windows-MCP 元素引用可继续执行点击；
- 语义程序支持窗口聚焦、缩放、最小化和恢复；
- 语义程序继续拒绝 ref、坐标、截图和 headed 模式；
- 视觉帧、窗口坐标、原子粘贴和 `visual_changed` 验证；
- 路径、策略、目标歧义和不可用状态失败关闭。
