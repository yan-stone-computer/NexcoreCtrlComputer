## 发现的问题

### 1. `press` 不支持键序列

模型输入 `642986*532=` 或按键数组时，旧实现只接受一个组合键，导致计算器测试失败。

修复：

- 支持 `keys` 数组；
- 支持数字/运算符组成的表达式字符串；
- 按顺序通过 Windows-MCP 注入按键；
- `*` 映射到数字键盘兼容的乘号输入，`=` 映射为回车求值。

真机回归：

```text
@s72qyh8wkh4pe:e6 statictext "显示为 342,068,552"
```

### 2. 桌面 `type/fill` 必须指定元素

保存对话框和部分编辑控件无法稳定返回元素 ref，模型只能用文件工具绕开 UI。

修复：

- `type/fill` 省略 target 时写入当前焦点；
- 使用 Windows-MCP 设置剪贴板后发送 `Ctrl+V`；
- 回执策略标记为 `windows-mcp-focused-type`。

真机回归：

- 在记事本编辑区写入“NexcoreWork 焦点输入保存测试”；
- 在另存为对话框用 `Alt+N`、粘贴绝对路径、回车保存；
- 文件真实存在且内容长度为 36 字节；
- 保存后标题为 `round2b-notepad-ui-save.txt - Notepad`，没有未保存星号。

### 3. 保存对话框无障碍树被截断

保存对话框的文件名输入框和“保存”按钮未稳定出现在摘要中。

已有替代路径：

```text
Ctrl+S
Alt+N
type 当前焦点文件名/绝对路径
Return
```

仍应继续改进对话框节点的定向查询，减少对快捷键路径的依赖。

### 4. 浏览器观察未直接返回页面标题

百度页面内容和 URL 可读，但首次标题值需要额外 `get title`。

修复：

- 浏览器 `observe` 主动读取并返回 `title`；
- 摘要文本同时包含 `title:`，模型不需要再猜或额外验证。

### 5. 前台锁导致窗口聚焦失败

Windows 拒绝后台进程直接抢占前台时，`window_focus` 和 Windows-MCP `App switch` 都可能失败。

现有保障：

- 最小化窗口先恢复；
- 原生聚焦失败后重试；
- 允许 headed 时点击标题栏兜底。

仍需继续加固：聚焦失败后应自动重枚举窗口并再次确认焦点，而不是把焦点错误传给后续输入。

## 未解决风险

- 部分权限模式下，工作区外保存会被策略拒绝；这是预期边界，不是文件系统 Bug。
- 某些保存对话框需要多个窗口或截图与快捷键混合才能完成。
- 浏览器启动和切换可能短暂抢占前台，产品应主动恢复 NexcoreWork 窗口或明确提示用户。
- `Windows-MCP` 的 `SetForegroundWindow` 仍可能被 Windows 前台锁拒绝。

## 结论

本轮不是“全部通过”。真实测试发现并修复了连续按键、焦点文本输入和浏览器标题读取三个核心问题；保存对话框和前台焦点仍需要持续加固。
